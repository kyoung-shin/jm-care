# E2E 테스트

실제 Chrome 을 띄워 배포된 화면을 눌러 보는 테스트입니다. Playwright 가 시스템에 설치된
Google Chrome 을 그대로 구동하므로 별도 브라우저 다운로드가 필요 없습니다.

## 실행

```bash
npm run e2e:pdf                                  # 배포본 대상, 브라우저 창 없이
E2E_HEADED=1 npm run e2e:pdf                     # 창을 띄워 동작을 눈으로 확인
E2E_BASE_URL=http://localhost:3000 npm run e2e:pdf
```

`.env.local` 의 `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `DATABASE_URL` 을 사용합니다.

## report-pdf.ts — 리포트 PDF 다운로드

`ReportModal` 안의 PDF 버튼 3개가 실제로 파일을 내려주는지 확인합니다.

| 버튼 | 위치 | 화면 |
| --- | --- | --- |
| `PDF로 저장` | 모달 헤더 | `/parent` |
| `PDF 내려받기` | 원장 검수 바 | `/director`, `/instructor` |
| `PDF 저장` | 모달 하단 | `/parent` |

함께 확인하는 것:

- 회차를 바꾸면 해당 기간의 PDF 가 내려오는지
- 받은 파일이 `%PDF-` 로 시작해 `%%EOF` 로 끝나는 정상 PDF 인지
- 파일명에 학생명과 기간이 들어가는지
- 중2 학생 화면에 `사회` 가 보이는지 (초·중 5과목)
- 성적 그래프 Y축이 `0~100` 고정이 아니라 실제 점수 구간으로 좁혀지는지

## 테스트 데이터

실행할 때마다 `ZZ_자동검증_<타임스탬프>` 지점과 그 안에 원장·강사·학부모 계정, 중2 학생
1명, 모의고사 4회, 발송 리포트 1건을 만들고 **끝나면 모두 지웁니다**(실패해도 정리됩니다).
이름이 `ZZ_자동검증_` 으로 시작하는 지점만 삭제 대상이라 운영 데이터는 건드리지 않습니다.

> `DATABASE_URL` 이 가리키는 DB 에 실제로 쓰기가 발생합니다. 운영 DB 를 대상으로 돌릴 때는
> 이 점을 감안해 주세요.

중단 등으로 정리가 안 된 경우, 다음 실행의 정리 단계에서 남아 있던 `ZZ_자동검증_*` 지점까지
함께 삭제됩니다.

## 산출물

스크린샷과 내려받은 PDF 는 임시 디렉터리에 저장되며 경로가 실행 로그 첫 줄에 출력됩니다.
